# バージョン7:「事例ファースト型」

## 狙い・フック解説

サービス説明を一切せず、ヒーローの1行目から実在物件の数字を見せる。「稼働率58%→82%」という Before/After は、伸び悩む乗り換えオーナーには「自分の物件との差」として、新規オーナーには「民泊はここまで回るのか」という相場観として、説明ゼロで刺さる。構成は帰納的に組む——①事例3本（乗り換え×2＋新規立ち上げ×1）→②「そこで何をしたか」を6本柱へ逆引き→③「では、あなたの物件なら？」と診断CTAへ着地。/switch から借りたのは Before/After 対比と損失額の計算提示。変えたのは順番で、/switch が「不満→解決策→事例」と演繹で下るのに対し、トップは「事例→手法→あなた」と帰納で上がる。成果は過去実績としてのみ語り、「あなたの物件でどうなるかは診断で確かめる」という誠実な接続でNG2（確約）を構造的に回避する。

### [Section 2: 事例①——乗り換えで稼働率を上げた野尻湖]

**セクション見出し:**
CASE 01｜野尻湖の貸別荘
稼働率 58% → 82%。月商 85万円 → 134万円。

**本文:**
他社代行からの乗り換え後、私たちが手を入れたのは派手な施策ではありません。

**「やったこと」逆引きリスト（✓形式）:**
- ✓ **価格を毎日、自動で調整した** — 数万件の宿泊データをもとに、季節・曜日・周辺イベントを織り込んだ最適価格を毎日設定。「年に数回見直す」運用とは打席数が違います。
- ✓ **OTAの掲載を毎月見直した** — タイトル・説明文・写真の順番・色味補正まで、毎月チューニング。初回設定で終わらせません。
- ✓ **24時間・4言語でゲストに応えた** — 日・英・中・韓。深夜の問い合わせに翌朝返すか、その場で返すか。レビューと再予約率はここで分かれます。

**結びの一文:**
打ち手は地味です。続けるかどうかが、58%と82%の差になりました。

### [Section 3: 事例②——単価を上げた京都]

**セクション見出し:**
CASE 02｜京都の宿泊物件
平均単価 ¥18,500 → ¥24,200（+30%）。レビュー 4.3 → 4.8。

**本文:**
「稼働率は悪くないのに、手残りが増えない」。単価が安すぎる物件によくある状態でした。値上げは怖い。でも、根拠があれば怖くありません。

**「やったこと」逆引きリスト（✓形式）:**
- ✓ **データで「取れる価格」を見極めた** — 感覚の値付けをやめ、数万件データの自動価格調整へ。埋めるための安売りから、適正価格で選ばれる運用に切り替えました。
- ✓ **写真と説明文を「単価が上がる順番」に組み替えた** — 同じ部屋でも、見せ方で予約者層は変わります。OTA掲載最適化を毎月実施。
- ✓ **清掃を100項目チェックリストで点検した** — 単価を上げてレビューが下がれば本末転倒。独自100項目の清掃・点検でレビューは4.3から4.8へ。

**結びの一文:**
単価+30%とレビュー上昇は、この物件では両立しました。
